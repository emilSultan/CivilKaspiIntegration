# Структура данных для кнопки «Заполнить ИнтернетМагазинРазмеры»

Данные вставляются в `ТабДок` (шапка в строке 1, данные — со строки 2). Колонки слева направо:

| № | Колонка         | Куда пишется в РегистрСведений.ИнтернетМагазинРазмеры                          |
|---|-----------------|----------------------------------------------------------------------------------|
| 1 | Division        | Ссылка на Справочник.MopDivision (поиск по Наименованию) → измерение MopDivision |
| 2 | Department      | Ссылка на Справочник.MopDepartment (поиск по Наименованию) → измерение MopDepartment |
| 3 | SubDepartment   | Ссылка на Справочник.MopSubDepartment (поиск по Наименованию) → измерение **Пол** (тип поля — MopSubDepartment, имя измерения в регистре вводит в заблуждение) |
| 4 | Category        | Ссылка на Справочник.MopCategory (поиск по Наименованию) → измерение MopCategory |
| 5 | Class           | Ссылка на Справочник.MopClass (поиск по Наименованию) → измерение **Категория** (тип поля — MopClass, имя измерения в регистре вводит в заблуждение) |
| 6 | Размер          | строка как есть → измерение Размер |
| 7 | Значение        | строка как есть → ресурс Значение |
| 8 | РазмерПродавца  | строка как есть → ресурс РазмерПродавца |
| 9 | РазмернаяCетка  | строка как есть → ресурс РазмернаяCетка (внимание: латинская "C", не кириллическая "С" — так называется поле в метаданных) |
| 10 | РосРазмерID    | строка как есть → ресурс РосРазмерID |
| 11 | РазмернаяCеткаID | строка как есть → ресурс РазмернаяCеткаID (латинская "C") |

Измерение `ИнтернетМагазин` регистра заполняется автоматически — берётся `Справочники.ИнтернетМагазины.НайтиПоКоду("000000001")` (тот же магазин Kaspi, что и в остальных кнопках обработки).

Колонки 1–5 (Division/Department/SubDepartment/Category/Class) идентичны формату, который уже используется в кнопках «Создать справочник мп_Категории» и «Загрузить меппинг» этой же обработки — если строка не находит соответствующий элемент в одном из справочников Mop*, она просто не попадёт в выборку (используется ВНУТРЕННЕЕ СОЕДИНЕНИЕ).

Реализация: `ЗагрузитьМеппингКаспи/Forms/Форма/Ext/Form/Module.bsl`, процедура `ЗаполнитьИнтернетМагазинРазмерыНаСервере`.

## Кнопка «Загрузить рост из ChildHeight_AI_Reference.md»

Данные вставляются в отдельный табличный документ `ТабДокРостAIReference` (шапка в строке 1,
данные — со строки 2), точно так же, как в `ТабДок` для кнопки «Заполнить ИнтернетМагазинРазмеры»:
таблицу из `ChildHeight_AI_Reference.md` копируют туда вручную, затем нажимают кнопку
`ЗагрузитьChildHeightAIReference`, которая пишет регистр `ИнтернетМагазинРазмеры`.

Колонки слева направо (как в `ChildHeight_AI_Reference.md`) и куда они пишутся:

| № | Колонка файла | Поле регистра `ИнтернетМагазинРазмеры` |
|---|---|---|
| 1 | `Department` | `MopDivision` |
| 2 | `Section` | `MopDepartment` |
| 3 | `Category` | `MopCategory` |
| 4 | `PurchaseGroup` | `Пол` (тип поля — `MopSubDepartment`) |
| 5 | `ProductGroup` | `Категория` (тип поля — `MopClass`) |
| 6 | `Size` | `Размер` |
| 7 | `Код Child body height` | ресурс `РазмерПродавца` |

Колонка 8 файла, `Наименование Child body height`, не записывается отдельно (по тексту самого
`ChildHeight_AI_Reference.md`: в `РазмерПродавца` идёт именно `Код Child body height`). Ресурсы
`Значение`, `РазмернаяCетка`, `РосРазмерID`, `РазмернаяCеткаID` этим источником не задаются.

Кнопка **только обновляет уже существующие записи регистра**, новых не создаёт: строка попадает
в запись, если (1) для неё нашёлся элемент во всех пяти справочниках `Mop*` (как и в остальных
кнопках — `ВНУТРЕННЕЕ СОЕДИНЕНИЕ`) И (2) в самом регистре `ИнтернетМагазинРазмеры` уже есть
запись с таким же набором измерений (`ИнтернетМагазин` + `MopDivision` + `MopDepartment` + `Пол`
+ `MopCategory` + `Категория` + `Размер`) — тоже проверяется через `ВНУТРЕННЕЕ СОЕДИНЕНИЕ`, теперь
с самим регистром. Если такой записи ещё нет, строка тихо пропускается (не создаётся).

Реализация: `ЗагрузитьМеппингКаспи/Forms/Форма/Ext/Form/Module.bsl`, процедура
`ЗагрузитьChildHeightAIReferenceНаСервере`.
